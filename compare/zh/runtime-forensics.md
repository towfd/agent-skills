TOPIC: 診斷執行中的程式

### 執行期鑑識

**診斷是你的責任。對執行中的程序做量測，不要從原始碼空想。** 要交的是附出處的診斷，不是修正。

1. 透過 control skill，在對應的介面上擷取即時訊號：程序一直空轉就抓 CPU 剖析檔，記憶體洩漏就抓 heap 快照，畫面出錯就抓 CDP 追蹤紀錄。要的是真實的擷取檔，不是猜測。
2. 把擷取檔縮減到確鑿的證據：熱路徑上的那個函式、從洩漏的物件到 GC root 的持有鏈、沒有輸入卻一直觸發的迴圈。大的擷取檔交給 subagent 解析（**guard-the-context-window** 這個原則 skill），主對話只留縮減後的發現。依工作挑每個 subagent 的推理等級，照 Subagents 那一節。
3. 相信機制之前，先證明它。在執行中的程序上用 CDP eval 注入量測，或不重新載入、直接熱修補正在跑的程式，用便宜的方式確認假設。
4. 把發現對回原始碼：檔案、符號、配置記憶體或排程的那一行。
5. 吞吐量檢查點只寫一行：`throughput checkpoint: n/a, read-only forensics`。

**回覆：** 擷取到的訊號、縮減後的發現、你怎麼證明機制、原始碼位置、擷取檔的路徑。沒被要求就不修。原因一確定，就交回 Bug fix（修 bug）或 Perf（效能問題）。
