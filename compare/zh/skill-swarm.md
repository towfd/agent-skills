# 蜂群

## 開始

派出任何東西之前，先開一個待辦清單，每個階段一項。

1. 界定框架
2. 分頭派出
3. 彙整
4. 回報

## 階段 A：界定框架

1. 講出完成的判斷條件，以及這次 swarm 必須交回的成品或報告。
2. 選好形狀。切成幾塊分給大家、讓 N 個工作者拿一模一樣的任務說明競速，或兩者混用。如果是競速或混合的形狀，派出之前先宣告 `first pass`、`rank all` 或 `best-of`。
3. 從 `~/.cursor/rules/pstack-models.mdc` 的 `swarm workers` 那一行挑工作者的模型。如果沒有這條規則或那一行，就用 `claude-opus-5-5-high-fast`。遇到 `auto` 或 `inherit-parent`，就省略 `model`，讓工作者用父層的模型跑。如果 Task 工具拒絕某個模型代號，就用預設值，並說出來。如果連預設值都被拒絕，就從它的錯誤訊息裡挑同一家族最接近的有效代號。如果是比模型的競速，事先寫出每一組用的模型。依工作挑每個 subagent 的推理等級，照 **poteto-mode** skill 的 Subagents 那一節。
4. 工作者會寫東西時，給每個工作者自己可以寫入的輸出位置。工作者要驗證或量測 commit 時，每份任務說明都要寫出確切的 SHA。量測的任務說明還要寫出方法（取樣次數、一次取樣是什麼、順序）。工作者在結果裡把這兩樣都記下來。

## 階段 B：分頭派出

在同一則訊息裡派出全部 N 個工作者，帶 `subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true`，以及第 3 步的模型，遇到 `auto` 或 `inherit-parent` 就不設定。只有在工作者需要用到使用者電腦上的東西時，才用 `environment: "local"`。

工作者必須從一個不是預設、已經推上去的分支開始時，傳 `cloud_base_branch`。

每份任務說明都要能單獨看懂。寫進目標、範圍、確切負責的那一塊或競速的那一組、怎麼驗證，以及要回報什麼。回報用 `PASS`、`ISSUES` 或 `BLOCKED`，並附上證據。能證明有缺陷的工作者回報 `ISSUES`，並列出它能證明的每一個問題，不是只列第一個。

如果有工作者退出，就用剩下的 N-1 個繼續，並記下來。

## 階段 C：彙整

讀最終的結果。結果裡沒記下任務說明指定的 SHA 和方法的，就丟掉，並把那個工作者重新派一次。第二次還是沒有，就記成一個缺口。缺口不算通過。如果是全面覆蓋，每一塊必要的部分都要有結果。如果是競速，就套用事先宣告的挑選規則。用 first pass、rank all 或 best-of。不要把工作者原始的輸出整包貼上。

## 階段 D：回報

在對話裡交回一份整合過的報告，內容有結果表格、每個問題一行、缺口或退出的工作者，有用競速時再加上競速規則。
