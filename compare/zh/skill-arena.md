# 競技場

派出任何東西之前，先開一個待辦清單，每個階段一項（界定框架、分頭派出、交叉評審、挑選、移植、驗證）。

## 階段 A：界定框架

每個候選者拿到的提示詞都一樣，所以提示詞就是約定。

1. 講清楚每個候選者要產出的成品是什麼。
2. 訂出評分標準：3 到 6 條具體、可以打分數的準則，說明在*這件*任務上成功長什麼樣子。它是階段 D 負責挑選的人用的工具。候選者只看得到任務。
3. 從 `~/.cursor/rules/pstack-models.mdc` 的 `arena runners` 那一行挑參賽者，預設是 `claude-fable-5-2-high`、`claude-opus-5-5-high-fast` 和 `gemini-4-neon-xhigh`。寫 `auto` 或 `inherit-parent` 的項目就是父層的模型，所以省略 `model`，派出 `generalPurpose`。如果 Task 工具拒絕某個模型代號，就用同一家族裡最接近的有效代號，或拿掉那個位子，至少留兩個參賽者，並說出來。家族看前綴來分，最長的符合者勝出：`claude-fable-*`、`claude-*` 和 `gemini-*`，比對前先去掉開頭的 `cursor-`。其他代號的家族，就是它第一個連字號之前的文字。要探索好幾個設計方向就多派幾個；工作卡在產出量、而不是靠判斷力時，就重複用同一個模型。依工作挑每個 subagent 的推理等級，照 **poteto-mode** skill 的 Subagents 那一節。
4. 照 **separate-before-serializing-shared-state** 原則 skill，給每個候選者自己的輸出位置（能用 git worktree 就用，不然就用 `/tmp/arena-<slug>/candidate-<n>/`）。

## 階段 B：分頭派出

在同一則訊息裡用 `run_in_background: true` 派出全部 N 個 subagent，每個都給：任務、共用背景資料的路徑、它自己的輸出路徑，以及指示：產出成品，再附一段簡短的理由，寫出它考慮過哪些替代做法、否決了什麼。

如果某個候選者沒有產出，就用剩下的 N-1 個繼續，並記下這個退出的候選者。

## 階段 C：交叉評審

階段 B 的候選者全部完成之後，從 `~/.cursor/rules/pstack-models.mdc` 的 `arena cross-judge pool` 那一行派出一個唯讀的評審，預設是 `claude-opus-5-5-high-fast`、`gemini-4-neon-xhigh`。評審絕不來自父層的廠商，而且做這項檢查時 Fable 算是 Claude，所以要用第一個來自別家廠商的項目。寫 `auto` 或 `inherit-parent` 的項目就是父層的模型。如果你不知道父層用的是什麼模型，就用第一個實際的模型代號，並說明沒有做廠商檢查。如果 Task 工具拒絕某個模型代號，就用同一家族裡最接近的有效代號，再不行就用下一個這樣的項目，或是跳過評審，並說出來。在你於階段 D 閱讀的同時，評審依路徑標籤，按評分標準的每一條替每個候選者打分數，並推薦一個基底。

## 階段 D：挑一個基底

挑之前，把每個候選者從頭到尾讀完。拿評分標準一條一條替每個打分數，不要憑整體的感覺，如果階段 C 有派評審，就跟交叉評審的結果比較。在基底上意見一致，就確認了這個選擇。意見不一致，代表你們其中一方有偏見，或評分標準有歧義。決定之前，兩邊的理由都要讀。

挑一個將來的維護者最容易擴充、又不會破壞不變條件的基底。兩個感覺不相上下時，照 Laziness Protocol（懶惰協定），選邊界比較乾淨或 API 比較小的那個。

## 階段 E：移植

把每個落選的候選者再走過一遍，找出值得搬進基底的東西，通常每個候選者一兩樣，不是大部分。照 **redesign-from-first-principles** 原則 skill，每個移植都用手融進去，讓結果在同一套心智模型下保持一致。不要機械式地貼上。

如果候選者都收斂到同一個形狀，那就是強烈的共識。把它記下來，出貨這個共識的形狀。不需要移植。如果它們差異大到離譜，就是階段 A 沒講清楚。重新界定框架再跑一次，不要把分歧平均掉。

## 階段 F：驗證

照 **prove-it-works** 原則 skill，像驗證任何其他輸出一樣，驗證這個綜合出來的成品。如果驗證找到這場 arena 漏掉的問題，不是階段 A 錯了（重新界定框架再跑一次），就是有個候選者抓到了、而你漏了那個移植（回到階段 E）。不要把它掩蓋過去。

## 產出

一份綜合出來的成品，旁邊附一份簡短的綜合說明，寫出：基底是哪個、為什麼；交叉評審的判定，或階段 C 跳過了評審；每個移植和它來自哪個候選者；否決了什麼、為什麼；有沒有收斂或退出的情況；以及驗證結果。
