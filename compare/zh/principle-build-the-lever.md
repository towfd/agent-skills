# 做出槓桿

當工作不算小的時候，做出能完成它的工具（codemod、腳本、產生器，或可以重跑的檢查），不要用手做。門檻看的是瑣不瑣碎，不是重不重複。只有遇到幾個明顯的修改時，才跳過做工具。

- 第一個單元用手做，然後做出工具，並在那個單元上重跑它來證明它。讓它可以安全地重跑。
- 結果固定的工具勝過分頭派工。真的要分頭派工時，把做法、驗證約定和界線寫成一份 skill，讓被委派的 agent 讀，而且改不了。
- 套用這條原則會產生一個檔案。diff 裡沒有腳本、codemod、產生器或委派用的 skill，就代表你沒有套用它。當這份工作會延續到這段對話結束之後，就把它 commit 進去。
- 做出能完成或證明這件工作的最小腳本，絕不做成一個框架。
