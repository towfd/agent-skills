# 測行為，不測實作

一個測試是一個主張，主張的是程式的使用者透過它的介面觀察得到什麼：回傳值、錯誤、他們讀得回來的狀態，以及對外部系統造成的影響。私有的輔助函式、內部的呼叫順序和中間資料，都是實作。

用兩個想像的修改來判斷每一個測試：

- **把行為弄壞**（一個錯的值、一個被跳過或做了兩次的效果）。如果測試還是通過，它什麼都證明不了。常見的原因是斷言太鬆、預期值是由被測的程式算出來的，以及斷言的是測試自己造出來的資料。
- **改變內部**，同時保留每一個觀察得到的結果。如果測試失敗，它就是被綁死在實作上。

保留能抓到第一種修改、又撐得過第二種修改的測試。其餘的改寫或刪掉。透過公開介面、用一個具體的輸入來驅動程式，並從需求推出預期值。外部服務收到什麼，是行為。對內部輔助函式的一次呼叫，不是。「這永遠不會發生」要搭配一個它真的發生的案例。斷言呼叫者會依據它來分支的錯誤型別，不要斷言錯誤訊息。
