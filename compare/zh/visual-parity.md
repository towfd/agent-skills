TOPIC: 遷移元件畫面不變

### 視覺一致

**像素完全相同是你的責任。基準就是規格。你不能碰它。** 相不相同用圖片 diff 驗證，不是用眼睛看。

1. 在任何遷移之前，先建立基準：一套視覺回歸測試工具，把目前的元件在各種狀態下截圖；如果是要讓兩套實作一致，連目標也截。沒有基準，就不能宣稱一致。這是擋在前面的先決條件，不是之後再補的事。
2. 防走捷徑的條款，要講出來並且守住：不改測試工具、不竄改基準、不為了讓 diff 通過而改元件結構。如果基準看起來不對，停下來問，不要改它。
3. 一次遷移一個元件。分散到多個 worktree 平行做，每個元件一個負責人（**separate-before-serializing-shared-state** 這個原則 skill）。共用的基礎元件先遷移，當成擋在前面的一個階段。
4. 透過 control skill 在對應的介面上，用圖片 diff 把每個元件和它的基準比對驗證。diff 不是零就是失敗。去查像素差在哪裡。每個元件各自 `/loop`，直到 diff 為零。
5. 每個元件，或每一批安全的修改，跑一次 **Opening a PR**（開 PR）。

**回覆：** 遷移了哪些元件、每個的 diff 結果、基準測試工具的位置、還剩什麼。
