TOPIC: 自己跑到完成

### 自主執行

**結束條件是你的責任。先定義怎樣算完成，然後不停地推進到那裡。**

1. 在第一輪之前，把結束條件講成一個可以檢查的判斷條件（測試全綠、重現的問題修好了、N 個 PR 全部合併、像素差異為零）。
2. 用 Cursor 的 `/loop` 指令（內建的，不是 pstack 的 skill）選喚醒機制。有事件可以盯的（CI、一次合併、一個 ref 往前推進），就派一個監看的 subagent，在事件發生時叫醒你，再加一個間隔很長的定時心跳當備援。沒有事件可盯的，就用固定間隔的心跳，間隔長短照結果什麼時候值得再檢查一次來定。依工作挑每個 subagent 的推理等級，照 Subagents 那一節。
3. 每一輪做證據撐得起的最小改動，拿判斷條件驗證它，有推進就 commit，沒幫助的改動就丟掉。「可能有幫助」的雙重保險要退回，不能放著跟著跑。
   照 **sequence-verifiable-units** 原則 skill 安排工作的順序，每個單元驗完再做下一個，不要把檢查全部堆到最後一起做。
4. 執行中途發現、對目標有幫助的事，都歸你。壞掉的 skill、相關的 bug、時好時壞的驗證工具、審查的雜訊、工具故障、沒人接手的後續事項，以及修得了的偏差，都透過 poteto-mode 自己處理。主線以外的修正放進它們自己的 PR。不要把改得回來的工作擱著等人，也不要用 `AskQuestion`。只提出不可逆的動作、沒有實驗能定案的真正產品或偏好選擇，或真的走到死路。讓判斷條件一直當主要的推進力，每做完一個旁支修正就回到它。
5. 每一輪都用 **show-me-your-work** skill 留檢查點，一列寫改了什麼、判斷條件有沒有動。
6. 判斷條件達成就停。停滯不算停下的理由，所以繼續做，並換個做法突破它。真的走到死路就提出來，不要原地打轉，而且絕不為了宣布勝利而放寬判斷條件。

**回覆：** 結束條件、跑過的輪次、哪些落地了、哪些丟掉了、判斷條件最後的狀態。
