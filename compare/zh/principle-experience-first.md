# 體驗優先

當實作方便和使用者開心互相衝突時，選使用者開心。

- 每一個功能、控制項和選項都必須有存在的理由
- 出少一點，出好一點（只有三個功能但精緻的體驗，勝過有十個功能但粗糙的體驗）
- 定案之前先做原型（設計決定在用完即丟的 HTML 裡做，比在正式程式碼裡做便宜）
- 把細節做對（轉場、對齊、間距、回饋、錯誤狀態）
- 把核心迴圈收緊（每個功能都應該服務主要的工作流程，不然就讓開）

使用者是任何使用這份工作成果的人。對 UI 來說，那是最終使用者。對函式庫或內部 API 來說，是匯入它的同事。下一個維護這份程式的工程師也是使用者。用同樣的方式看重他們的體驗，並從他們的角度說明影響。

根基應該為體驗服務。「從根基想」管的是工作的*順序*。這條原則管的是*目標*。
