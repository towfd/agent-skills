# 解釋那個數字

- **跑之前先把決定寫下來。** 說出什麼樣的結果會改變這個決定，以及雜訊的底線。當每次執行之間的落差比效果還大時，就停下來。
- **問「為什麼不是兩倍？」** 說出限制住這個結果的資源或程式路徑，根據要是執行當中取得的效能剖析或計數器。讀程式碼得來的猜測不算限制因素。
- **列出這個數字還可能在量什麼**（錯誤、被跳過或用了快取的工作、根本沒跑到的程式、沒調校過的那一邊、雜訊、小到無關緊要的一塊），並用證據逐一排除。
- **把執行次數、落差和限制因素跟數字放在一起。**

如果是效能數字，跑 [benchmark-checklist](../benchmark-checklist/SKILL.md) skill。如果是評測結果，要問每一次執行是不是都真的做了那件任務、差距在多次試驗和不同模型之間是否都成立，以及這個情境重不重要。
