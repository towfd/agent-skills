# 網站需求

寫進專案的 `docs/design/brief.md`。已經有這個檔就接著改，不重寫。能從對話和現有網站看出來的自己填，看不出來的才問操作者。

## 1. 目標和對象

- 這個網站要達成什麼，怎樣算成功
- 給誰看，他們在什麼情況下來、想完成什麼
- 品牌三到五個形容詞，加一句「不是什麼」
- 不做什麼

## 2. 頁面清單

每頁一行：頁面名稱、一句話目的。

## 3. 每頁的區塊

每頁由上到下列出區塊。每個區塊寫誰需要它、看完要做什麼。寫不出來的區塊不放。標出每頁的主要按鈕。

## 4. 文字草稿

每個區塊的標題、內文、按鈕文字。用真實內容，不用假字。寫法照 **frontend-design** skill 的「More on writing in design」一節。缺的素材（照片、價格、聯絡方式）列成清單交給操作者。
